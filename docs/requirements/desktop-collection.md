# 桌面收纳功能需求

> **状态**：需求草案（与当前实现存在差距，见 [附录 A](#附录-a与当前实现的差距待确认)）
> **配套工程约束**：[AGENTS.md](../../AGENTS.md) —— 技术选型、依赖边界、验证门槛、禁止事项以该文件为准。
> 本文件只回答"做什么"：产品行为、数据模型、持久化语义、拖放协议、崩溃恢复与验收标准。

---

## 1. 背景与目标

Windows 桌面**手动拖拽收纳**工具。用户可将桌面或资源管理器中的文件、文件夹、快捷方式**拖入半透明悬浮收纳窗（栅栏）**完成整理；**文件物理位置不变**，栅栏仅持有路径引用。

- **产品形态**：半透明悬浮栅栏，手动拖拽收纳，可收起/展开，支持多栅栏分组。
- **资源纪律**：常驻空闲 **0% CPU**，内存基线保持个位数 MB 量级。
- **安全哲学**：只引用、不移动；任何退出路径自动恢复桌面原始状态；删除可撤销。

## 2. 核心数据模型

### 2.1 两类栅栏成员必须显式区分

项目同时存在两类"栅栏成员"，**必须在数据模型中显式区分，不得共用同一结构体而不加标记**：

| 类型 | 来源 | 身份 / 字段 |
|---|---|---|
| **桌面接管图标** `DesktopIconRef` | `shell` 层通过 WorkerW/DefView 接管枚举得到的桌面图标引用 | 身份由桌面图标位置或系统 PIDL 标识 |
| **手动收纳项** `CollectedItem` | 用户从桌面或资源管理器拖拽进来的文件、文件夹、快捷方式 | `core` 层持有：**路径引用**、显示名、图标缓存键、所属栅栏 ID、加入时间、排序键 |

### 2.2 引用语义

- 收纳项与栅栏是**引用关系，不是移动关系**。
- **文件物理位置不变**；禁止在拖入时移动或复制磁盘文件。

### 2.3 桌面临 → 收纳列表的状态迁移

从桌面拖入收纳栅栏时，若该文件同时被桌面接管列表持有，必须执行**显式的状态迁移**：

- 从接管列表移入收纳列表，**或**
- 标记为"已被收纳"并从接管渲染中排除。

**不得出现同一文件在两处重复显示。**

### 2.4 失效引用

- 收纳项路径失效（文件被外部删除或移动）时，必须标记为**"失效引用"**。
- UI 中降级显示，并提供"移除引用"操作。
- **不得导致渲染崩溃。**

### 2.5 删除与可撤销队列

- 收纳项的删除必须进入**可撤销队列**；撤销记录**持久化，重启后仍可恢复**。
- 删除收纳项**不得删除磁盘文件**，仅移除引用。

### 2.6 领域命令

收纳项排序、栅栏归属变更、显示名修改等操作，必须通过 `core` 层的**领域命令**执行；不得由 `render` 或 `shell` 直接修改持久化状态。

## 3. 持久化

### 3.1 存储引擎与位置

- 存储引擎：**`redb`**（纯 Rust 嵌入式键值存储，ACID 事务、稳定文件格式）。
- 所有配置读写必须经 `DeskStore` 抽象（见 [存储后端设计](../design/storage-backend.md)）；JSON 与 redb 均为可替换后端，迁移/导出通过统一快照复制完成。
- 存储位置：用户 **AppData** 目录下的**单一 `redb` 文件**（⚠️ 与当前实现冲突，见附录 A）。
- 数据模型：栅栏布局、收纳项引用、规则配置、布局快照，以结构化键值对序列化存储。

### 3.2 序列化

- 配置与快照序列化格式：**JSON（`serde_json`）**。
- 非核心文件（配置导出、快照等）采用 **write temp → rename** 原子替换。

### 3.3 事务边界

- **所有跨多个键的写入必须包裹在单个 `redb` write transaction 中**，禁止"先写收纳项、再写栅栏索引"的分步提交。
- 若事务提交失败，内存状态必须回滚到事务开始前的快照，并向 `app` 层返回**结构化错误**。
- 不得让 UI 显示未持久化的"幽灵收纳项"。

### 3.4 快照与回滚

- 任何由用户或 AI 发起的**批量配置变更**（批量添加/移除收纳项、批量调整栅栏布局、导入规则），变更前必须**自动生成快照**。
- 快照必须包含：栅栏布局、收纳项引用集合、规则配置、时间戳、快照 ID。
- 快照可用于回滚；**回滚操作本身也必须记录为可撤销操作**，形成可追溯的操作链。

### 3.5 图标缓存

- 图标允许缓存，但缓存键必须基于**文件路径 + 文件修改时间 + 图标尺寸**，不得仅基于路径。
- 缓存必须有**容量上限与淘汰策略**，禁止无上限增长。
- 图标缓存属于**可重建数据**，不得与核心配置混在同一 `redb` table 中；应使用独立 table 或独立缓存文件，损坏时可安全丢弃重建。

## 4. 系统集成

### 4.1 桌面接管

- WorkerW/DefView 接管必须是**低风险**的：使用窗口消息 / COM 接口，**不注入 DLL，不替换系统 shell**。
- 不得干扰 Wallpaper Engine 或其他桌面美化工具的已知安全边界。
- 多显示器与 DPI 变化必须优雅降级，不得导致崩溃或图标丢失。
- 主窗口启动时按需隐藏并嵌入目标层；**嵌入失败最多重试 3 次**，失败后降级为普通悬浮窗并记录日志。
- 桌面接管状态必须可被**独立查询**；`app` 层不得假设"接管一定成功"。

### 4.2 拖放接收（OLE `IDropTarget`）

- 每个栅栏 overlay 窗口必须在 `shell` 层注册 **OLE `IDropTarget`**。
- `DragEnter` / `DragOver` 必须检查 `IDataObject` 是否包含 **`CF_HDROP`**；不支持的类型必须返回"不可放置"状态，**不得静默吞掉**。
- `DragOver` 必须根据修饰键与目标栅栏状态返回正确的放置效果（复制 / 移动 / 链接 / 无操作），**不得始终返回"允许"**。
- `Drop` 提取路径列表后，必须校验路径合法性（存在性、长度、权限、是否为系统保护路径），再交给 `core` 层。
- 拖放必须在 `render` 层提供明确的**悬停高亮反馈**；`DragLeave` 与 `Drop` 完成后必须清除反馈状态。
- 拖放结果（成功 / 失败 / 部分成功）必须以**结构化结果**返回并记录日志；部分失败时必须保留成功项并报告失败原因。
- 从栅栏拖出文件到桌面或资源管理器时，必须遵循**系统拖放语义**，不得伪造或劫持拖放源。

### 4.3 崩溃恢复与退出

- **任何退出路径**（正常退出、崩溃、用户注销、系统关机）都必须**自动恢复桌面图标原始状态**。
- 恢复逻辑必须**独立于主渲染循环**，不依赖 UI 线程存活；建议在 `shell` 层维护独立的恢复守卫。
- 删除或移动收纳项的操作必须是**事务性**的：失败时回滚，不得留下半完成状态。
- 全局退出必须清理所有 overlay 窗口、COM 引用与 `redb` 事务句柄。
- 程序启动时必须检测上一次会话是否异常退出；若存在**未完成的恢复标记**，必须先执行桌面恢复再进入正常初始化。

## 5. AI 配置接口

吸收 PecoFence 的"AI 一等公民"理念：AI 代理应能通过**结构化、可预览、可回滚**的接口配置本应用，而不必理解内部渲染细节。

- 对外暴露稳定的**结构化配置接口（JSON Schema）**，可通过 CLI 或本地 IPC 调用。
- 任何由 AI 发起的配置变更必须支持 **`--dry-run` 预览**，并自动备份变更前快照。
- 变更结果以**结构化 JSON** 返回：成功/失败、影响的栅栏与规则列表、回滚快照 ID。
- CLI 必须是**无 GUI 依赖的独立二进制**；即使主进程崩溃，AI 代理仍可读取配置并触发恢复。
- CLI 与核心逻辑**共享 `core` 层的模型与校验**，不得出现两套并行的配置语义。
- CLI 不得绕过 `core` 层的事务与校验直接写 `redb`；所有写操作必须复用领域命令。

## 6. 验收标准

### 6.1 功能验收

- [ ] 从资源管理器拖入文件/文件夹到栅栏成功，悬停高亮正确。
- [ ] 从栅栏拖出文件到桌面/资源管理器，行为符合系统拖放语义。
- [ ] 拖入不支持的类型时显示"不可放置"，且不产生任何副作用。
- [ ] 从桌面拖入的文件不再在桌面接管列表中重复显示。
- [ ] 删除收纳项后，撤销记录在**重启后**仍可恢复，且磁盘文件未被删除。
- [ ] 文件被外部删除后，收纳项降级为"失效引用"，可移除且不崩溃。
- [ ] 批量变更前自动生成快照，可回滚；回滚本身进入撤销链。
- [ ] 模拟事务失败：内存状态回滚，UI 不出现"幽灵收纳项"。
- [ ] 异常退出（强杀）后重启，桌面恢复守卫正确执行。
- [ ] 多显示器与 DPI 缩放切换无异常。
- [ ] 空闲时 CPU 0%，常驻内存保持个位数 MB 量级（启动期修剪后）。

### 6.2 兼容性验收

- [ ] 在 **Windows 10** 与 **Windows 11** 上分别验证上述条目。
- [ ] 与 Wallpaper Engine 等桌面美化工具共存，不干扰其窗口树。
