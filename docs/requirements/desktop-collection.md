# 桌面收纳功能需求

> **状态**：P0 需求已实现（P0-00 + P0-01～P0-06，见 [P0 实施记录](../design/p0-implementation.md)）；Windows 10/11 人工验收待执行，剩余差距见 [附录 A](#附录-a与当前实现的差距待确认)
> **配套工程约束**：[AGENTS.md](../../AGENTS.md) —— 技术选型、依赖边界、验证门槛、禁止事项以该文件为准。
> 本文件只回答"做什么"：产品行为、数据模型、持久化语义、拖放协议、崩溃恢复与验收标准。

---

## 1. 背景与目标

Windows 桌面**手动拖拽收纳**工具。用户可将桌面或资源管理器中的文件、文件夹、快捷方式**拖入半透明悬浮收纳窗（栅栏）**完成整理；**文件物理位置不变**，栅栏仅持有路径引用。

- **产品形态**：半透明悬浮栅栏，手动拖拽收纳，可收起/展开，支持多栅栏分组。
- **资源纪律**：常驻空闲 **0% CPU**，内存基线保持个位数 MB 量级。
- **安全哲学**：只引用、不移动；任何退出路径自动恢复桌面原始状态；删除可撤销。

## 2. 核心数据模型

### 2.1 两类栅栏成员必须显式区分

项目同时存在两类"栅栏成员"，**必须在数据模型中显式区分，不得共用同一结构体而不加标记**：

| 类型 | 来源 | 身份 / 字段 |
|---|---|---|
| **桌面接管图标** `DesktopIconRef` | `shell` 层通过 WorkerW/DefView 接管枚举得到的桌面图标引用 | 身份由桌面图标位置或系统 PIDL 标识 |
| **手动收纳项** `CollectedItem` | 用户从桌面或资源管理器拖拽进来的文件、文件夹、快捷方式 | `core` 层持有：**路径引用**、显示名、图标缓存键、所属栅栏 ID、加入时间、排序键 |

> 实现说明：当前用 `Icon.origin: ItemOrigin`（`DesktopIcon` / `Collected`）显式标记来源；
> `added` 仅保留为旧配置反序列化兼容字段，新逻辑不得用它判断来源。

### 2.2 引用语义

- 收纳项与栅栏是**引用关系，不是移动关系**。
- **文件物理位置不变**；禁止在拖入时移动或复制磁盘文件。
- 链接文件夹栅栏只做目录镜像；用户主动移除镜像项时写入 `Fence.suppressed_paths`，
  同步周期跳过该路径，文件保留在磁盘。

### 2.3 桌面临 → 收纳列表的状态迁移

从桌面拖入收纳栅栏时，若该文件同时被桌面接管列表持有，必须执行**显式的状态迁移**：

- 从接管列表移入收纳列表，**或**
- 标记为"已被收纳"并从接管渲染中排除。

**不得出现同一文件在两处重复显示。**

### 2.4 失效引用

- 收纳项路径失效（文件被外部删除或移动）时，必须标记为**"失效引用"**。
- UI 中降级显示，并提供"移除引用"操作。
- **不得导致渲染崩溃。**
- 实现：`Icon.invalid` 标记；同步周期只更新标记、不删除引用；渲染降透明度；
  右键菜单提供"移除引用"；路径恢复后自动清除标记。

### 2.5 删除与可撤销队列

- 收纳项的删除必须进入**可撤销队列**；撤销记录**持久化，重启后仍可恢复**。
- 删除收纳项**不得删除磁盘文件**，仅移除引用。
- 实现：`Desk.undo`（容量 50）随主配置单事务保存；托盘"撤销上一步删除"与 `Ctrl+Z`；
  Shell 原生"删除"动词被隐藏，右键统一提供"移除引用/移出栅栏"；批量删除只生成一条记录。

### 2.6 领域命令

收纳项排序、栅栏归属变更、显示名修改等操作，必须通过 `core` 层的**领域命令**执行；不得由 `render` 或 `shell` 直接修改持久化状态。

### 2.7 多栅栏分类（空白栅栏 / 收件箱 / 门户）

栅栏分三类，显式持久化，不得靠 `storage_path` 有无猜测：

| 类型 | 作用 |
|---|---|
| `Manual` 普通/空白栅栏 | 成员完全由用户拖入决定；不绑定目录 |
| `DesktopInbox` 桌面收件箱 | 全局唯一；启动时实时扫描“用户桌面 + 公共桌面”，作为未分类图标的入口；缺失时自动补建。只读：拒绝拖入/粘贴/删除引用；从收件箱拖到其他栅栏或资源管理器均为复制。 |

> 桌面上的“此电脑/回收站”等虚拟 Shell 项不是文件路径，当前不进入收件箱；隐藏/系统文件按资源管理器默认不镜像。
| `FolderPortal` 文件夹门户 | 镜像指定文件夹；成员关系只读，由目录决定 |

规则：

- 新建栅栏必须提供“空白栅栏”入口，不得强制选择文件夹；桌面空白右键保留 Windows
  原始菜单，并在末尾追加常驻 Sylva 子菜单（新建空白栅栏 / 链接文件夹 / 新建收件箱 /
  打开控制中心 / 切换栅栏或原始桌面）。Sylva 子菜单在栅栏模式、原始桌面、Quick hide 下都出现，
  其他应用/任务栏右键不得被拦截。
- 从收件箱把图标拖到普通栅栏：默认**移动**（源收件箱写入 `suppressed_paths`，目标增加引用）；
  `Ctrl` 拖拽为**复制引用**，两处都显示。
- 跨栅栏拖放必须经 `core` 的 `classify_move` 领域命令；多选产生**一条**撤销记录。
- 离开源栅栏后需给用户穿过空隙进入目标栅栏的时间（当前 400ms 延迟后才启动 OLE 拖出）；
  按住 Shift 可立即拖出到桌面/资源管理器。
- 文件夹拖入普通栅栏时，用户显式选择“文件夹图标”或“链接为文件夹门户”；不得静默决定。
- 文件夹门户**只读**：拖入返回不可放置；拖出遵循系统拖放语义；删除/移出只移除引用，
  文件保留；用户主动移除用 `suppressed_paths` 防止 4 秒同步回加。
- 同一文件默认只属于一个分类栅栏；收件箱与分类栅栏之间禁止重复显示。`Ctrl` 复制是显式例外。
- 空白栅栏、收件箱、门户类型均持久化；`Desk.version` 3 迁移旧 `storage_path` 栅栏为门户，
  并把镜像桌面目录的旧栅栏升级为唯一收件箱。

### 2.8 栅栏外观与设置

每个栅栏的外观配置必须可独立持久化：

- **标题**：可关闭标题；关闭后标题栏一并隐藏，栅栏空白区域拖动移动（该栅栏不再支持橡皮筋框选）。
- **图标名称**：可关闭栅栏内所有名称标签；关闭后悬停工具提示也不显示名称。
- **网格行列**：控制中心使用 8×8 个 32px 小格的选择器；支持按下拖拽选择列/行（从 1×1 到目标格），松开后栅栏实际宽高同步变化；超出可见行后滚动。
- **背景**：支持玻璃 / 描边 / 纯色 / 模糊；填充不透明度使用 0–100 滑轨（支持按住拖拽），默认 80；支持系统色板预设与系统颜色选择器自定义色调。
- **控制中心**：不使用长条式单页，采用**左侧导航 + 右侧内容**的主从结构；左侧固定「系统控制」和全部栅栏，右侧显示系统功能或选中栅栏的布局/外观设置；新建栅栏入口固定在左侧底部。
- **默认尺寸**：首次打开控制中心时宽高各约为主屏的 1/3；用户拖拽缩放后持久化自定义尺寸，系统页提供“重置面板尺寸”。
- **字体/控件缩放**：按 DPI × 实际屏幕面积计算，显示尺寸/DPI 变化后重新计算。
- **选中联动**：控制中心选中栅栏时，实体栅栏绘制高对比强调边框。
- **图标形状**：支持方角 / 圆角 / 圆形。
- **悬停效果**：支持关闭 / 仅高亮 / 放大，可持久化。
- **选中视觉**：网格/侧边栏选中占位是围绕图标中心的正方形（列内居中）；列表选中整行。
- **全局叠加**：系统控制提供“允许栅栏叠加”开关；关闭时移动/缩放保持间距，开启后可互相覆盖。
- **显示控制**：每个栅栏可独立隐藏/显示；隐藏后成员保留，仍可在控制中心重新显示。
- **重命名**：控制中心选中栅栏后可直接重命名；右键菜单也可重命名。
- **右键菜单**：桌面/图标/栅栏右键优先保留 Windows 原有功能，再追加 Sylva 子菜单；栅栏右键可“在控制中心管理此栅栏”和“选择全部项目”。
- **内边距**：栅栏内容区上下左右使用同一份 padding，不因标题栏/自动高度产生额外留白。
- 所有外观修改必须即时生效并持久化；旧配置缺少新字段时取默认值，不得导致加载失败。

## 3. 持久化

### 3.1 存储引擎与位置

- 存储引擎：**`redb`**（纯 Rust 嵌入式键值存储，ACID 事务、稳定文件格式）。
- 所有配置读写必须经 `DeskStore` 抽象（见 [存储后端设计](../design/storage-backend.md)）；JSON 与 redb 均为可替换后端，迁移/导出通过统一快照复制完成。
- 存储位置：**exe 同级 `data/` 目录**下的单一 `redb` 文件（与安装器卸载约定一致；2026-11-12 确认）。
- 兼容策略：首次启动若检测到旧 `desk.json` 而 redb 为空，自动导入并备份为 `desk.json.bak`；`SYLVA_STORE=json` 可显式回退旧后端。
- 数据模型：栅栏布局、收纳项引用、规则配置、布局快照，以结构化键值对序列化存储。

### 3.2 序列化

- 配置与快照序列化格式：**JSON（`serde_json`）**。
- 非核心文件（配置导出、快照等）采用 **write temp → rename** 原子替换。

### 3.3 事务边界

- **所有跨多个键的写入必须包裹在单个 `redb` write transaction 中**，禁止"先写收纳项、再写栅栏索引"的分步提交。
- 若事务提交失败，内存状态必须回滚到事务开始前的快照，并向 `app` 层返回**结构化错误**。
- 不得让 UI 显示未持久化的"幽灵收纳项"。

### 3.4 快照与回滚

- 任何由用户或 AI 发起的**批量配置变更**（批量添加/移除收纳项、批量调整栅栏布局、导入规则），变更前必须**自动生成快照**。
- 快照必须包含：栅栏布局、收纳项引用集合、规则配置、时间戳、快照 ID。
- 快照可用于回滚；**回滚操作本身也必须记录为可撤销操作**，形成可追溯的操作链。
- 实现：快照存于独立 JSON 目录或 redb `snapshots` 表，保留最近 10 份；结构性变更前自动生成；
  启动主配置解析失败时回退最近快照；恢复前先为当前状态生成快照，并把 `RestoreSnapshot`
  压入撤销链。

### 3.5 图标缓存

- 图标允许缓存，但缓存键必须基于**文件路径 + 文件修改时间 + 图标尺寸**，不得仅基于路径。
- 缓存必须有**容量上限与淘汰策略**，禁止无上限增长。
- 图标缓存属于**可重建数据**，不得与核心配置混在同一 `redb` table 中；应使用独立 table 或独立缓存文件，损坏时可安全丢弃重建。

## 4. 系统集成

### 4.1 桌面接管

- WorkerW/DefView 接管必须是**低风险**的：使用窗口消息 / COM 接口，**不注入 DLL，不替换系统 shell**。
- 不得干扰 Wallpaper Engine 或其他桌面美化工具的已知安全边界。
- 多显示器与 DPI 变化必须优雅降级，不得导致崩溃或图标丢失。
- 主窗口启动时按需隐藏并嵌入目标层；**嵌入失败最多重试 3 次**，失败后降级为普通悬浮窗并记录日志。
- 桌面接管状态必须可被**独立查询**；`app` 层不得假设"接管一定成功"。

### 4.2 拖放接收（OLE `IDropTarget`）

- 单个 overlay 窗口必须在 `shell` 层注册 **OLE `IDropTarget`**，按栅栏命中矩形分发
  （原"每个栅栏一个 overlay"改为"单 overlay + 每栅栏命中区域"，行为等价、成本更低）。
- `DragEnter` / `DragOver` 必须检查 `IDataObject` 是否包含 **`CF_HDROP`**；不支持的类型必须返回"不可放置"状态，**不得静默吞掉**。
- `DragOver` 必须根据修饰键与目标栅栏状态返回正确的放置效果（复制 / 移动 / 链接 / 无操作），**不得始终返回"允许"**。
  虚拟栅栏只持有引用，默认返回 `LINK`；**禁止返回 `MOVE`**，避免资源管理器删除源文件。
- `Drop` 提取路径列表后，必须校验路径合法性（存在性、长度、权限、是否为系统保护路径），再交给 `core` 层。
- 拖放必须在 `render` 层提供明确的**悬停高亮反馈**；`DragLeave` 与 `Drop` 完成后必须清除反馈状态。
- 拖放结果（成功 / 失败 / 部分成功）必须以**结构化结果**返回并记录日志；部分失败时必须保留成功项并报告失败原因。
- 从栅栏拖出文件到桌面或资源管理器时，必须遵循**系统拖放语义**，不得伪造或劫持拖放源；
  使用 `IDropSource` + `SHDoDragDrop` 与系统 `CF_HDROP` 数据对象。

### 4.3 崩溃恢复与退出

- **任何退出路径**（正常退出、崩溃、用户注销、系统关机）都必须**自动恢复桌面图标原始状态**。
- 恢复逻辑必须**独立于主渲染循环**，不依赖 UI 线程存活；在 `shell` 层维护恢复 API，
  `app` 层启动同二进制 `--recovery-guard <pid>` 独立守卫进程，并以 `data/recovery.marker`
  作为启动兜底。
- 删除或移动收纳项的操作必须是**事务性**的：失败时回滚，不得留下半完成状态。
- 全局退出必须清理所有 overlay 窗口、COM 引用与 `redb` 事务句柄。
- 程序启动时必须检测上一次会话是否异常退出；若存在**未完成的恢复标记**，必须先执行桌面恢复再进入正常初始化。

## 5. AI 配置接口

> **实现状态**：本轮未实现（P0-00～P0-05 之外，作为 L4 进程外工具单独排期）。以下为需求约束。

吸收 PecoFence 的"AI 一等公民"理念：AI 代理应能通过**结构化、可预览、可回滚**的接口配置本应用，而不必理解内部渲染细节。

- 对外暴露稳定的**结构化配置接口（JSON Schema）**，可通过 CLI 或本地 IPC 调用。
- 任何由 AI 发起的配置变更必须支持 **`--dry-run` 预览**，并自动备份变更前快照。
- 变更结果以**结构化 JSON** 返回：成功/失败、影响的栅栏与规则列表、回滚快照 ID。
- CLI 必须是**无 GUI 依赖的独立二进制**；即使主进程崩溃，AI 代理仍可读取配置并触发恢复。
- CLI 与核心逻辑**共享 `core` 层的模型与校验**，不得出现两套并行的配置语义。
- CLI 不得绕过 `core` 层的事务与校验直接写 `redb`；所有写操作必须复用领域命令。

## 6. 验收标准

> 实现状态：P0-00～P0-06 代码路径已落地，自动测试通过；下列涉及真实桌面/拖放/恢复的条目
> 仍需在 Windows 10/11 上人工验收后再勾选。已知边界见 [P0 实施记录](../design/p0-implementation.md#6-已知边界--后续)。

### 6.1 功能验收

- [ ] 从资源管理器拖入文件/文件夹到栅栏成功，悬停高亮正确。
- [ ] 从栅栏拖出文件到桌面/资源管理器，行为符合系统拖放语义。
- [ ] 拖入不支持的类型时显示"不可放置"，且不产生任何副作用。
- [ ] 从桌面拖入的文件不再在桌面接管列表中重复显示。
- [ ] 删除收纳项后，撤销记录在**重启后**仍可恢复，且磁盘文件未被删除。
- [ ] 文件被外部删除后，收纳项降级为"失效引用"，可移除且不崩溃。
- [ ] 批量变更前自动生成快照，可回滚；回滚本身进入撤销链。
- [ ] 新建空白栅栏不需要选择文件夹，拖入图标后重启仍保持。
- [ ] 从桌面收件箱拖到分类栅栏后，收件箱不再显示该图标；Ctrl 拖拽可显式复制到多个栅栏。
- [ ] 文件夹拖入普通栅栏可选择“文件夹图标”或“文件夹门户”；门户只读、目录变化自动同步。
- [ ] 跨栅栏移动/复制后撤销恢复原归属；磁盘文件未移动或删除。
- [ ] 栅栏可关闭标题文字与图标名称；关闭后仍可拖动、无名称提示。
- [ ] 网格栅栏可设置固定列数/可见行数、填充透明度和自定义颜色，重启后保持。
- [ ] 控制中心采用左侧导航 + 右侧内容；系统控制/栅栏切换正常，不再把所有控制堆成长条。
- [ ] 模拟事务失败：内存状态回滚，UI 不出现"幽灵收纳项"。
- [ ] 异常退出（强杀）后重启，桌面恢复守卫正确执行。
- [ ] 多显示器与 DPI 缩放切换无异常。
- [ ] 空闲时 CPU 0%，常驻内存保持个位数 MB 量级（启动期修剪后）。
