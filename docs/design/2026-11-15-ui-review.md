# Sylva 界面评审与视觉系统建议

> 状态：**B1 / B2 / B3 已落地**（2026-11-15），其余见文末「落地进度」。
> 已同步 `docs/requirements/desktop-collection.md` §2.8 与 `AGENTS.md` §5.3 人工验证清单。
> 评审对象：`crates/render`（draw / theme / scene / overlay）与 `crates/app`（scene / main）。

---

## 0. 结论先行

现在的问题不是"再调几个颜色、再加几个 padding"，而是**缺一套度量体系**，导致同一件事有三份数值来源：

- 栅栏内边距：布局用 `appearance.padding = 12`（`app/scene.rs:980`），标题与裁剪用 `theme.fence_padding = 14`（`render/draw.rs:1153`）——**同一栅栏左右各差 2px**，违反需求 §2.8「四边同一份 padding」。
- "大中小三档"只改了图标像素（32/48/64），格子宽高、标签宽度、行高、字号全是别的公式推出来的，所以三档**不是三档，是三个意外**。
- 名称标签是"两行 + 左对齐"（`GRID_CAPTION_H_MULT = 2.6`、`draw_caption`），图标高度却恒定——切名称开关时整块栅栏重排。
- 没有阴影、没有拖拽态、没有对齐线、没有桌面安全区：所以栅栏看起来"贴在壁纸上"，而不是浮在桌面上。

所以建议的动作顺序是：**先立三张表（间距 / 字号 / 单元格），再改七处交互，最后补产品能力**。

## 1. 设计判断

**平台定位**：Windows-first 的桌面原生工具，不是"应用窗口"。它寄生在桌面上，观感必须服从资源管理器与系统图标的既有语言，而不是自成一套 widget 风。

**目标观感**：三句话——

1. 远看"桌面变整齐了"，近看"像是 Windows 自带的东西"；
2. 栅栏是"半透明的收纳容器"，不是"卡片 App"；
3. 所有间距来自同一个 4px 节奏，所有圆角不超过两级。

**现状判断**：功能完整（布局三种、外观可配、控制中心主从结构都在），但视觉是"代码长出来的"：每个模块各自决定自己多宽多高，缺少一个统一定义"一个栅栏长什么样"的地方。

### 1.1 不协调的五个根因

| # | 根因 | 表现 |
|---|---|---|
| 1 | 度量多源 | padding 12/14 两套；gap 10/24 两套；圆角 12/8 两套；accent 两条蓝 |
| 2 | 无状态规范 | 栅栏本体没有 hover / dragging / resizing 视觉；只有图标有 |
| 3 | 无层级手段 | 栅栏和控制中心都是"圆角 + 描边"，没有阴影、没有 z 轴区分 |
| 4 | 控件是"行"不是"组" | 控制中心 12 个设置项平铺单列，扫读成本高 |
| 5 | 主题是硬编码 | 浅色模式下只翻边框颜色（`app/scene.rs:1249`），面板、强调色、文字全是深色常量 |

## 2. 先立三张表（所有修改的前提）

以下数值均为 **100% DPI 下的逻辑像素**，由 `Theme::scale` 统一放大。

### 2.1 间距 / 圆角 / 描边

| Token | 值 | 用途 | 现状 |
|---|---|---|---|
| `space-1/2/3/4/6` | 4 / 8 / 12 / 16 / 24 | 通用间距 | 6/8/10/12/14 混用 |
| `fence-pad` | 12 | 栅栏四边内边距（**唯一来源**） | 12 与 14 并存 |
| `fence-gap` | 12 | 栅栏之间最小间距 | 12（保持，已持久化） |
| `desktop-inset` | 12 | 桌面安全区（栅栏离屏幕边缘的最小距离） | **不存在** |
| `radius-control` | 8 | 按钮、分段控件、色块 | 8 左右但散落 |
| `radius-panel` | 12 | 栅栏、控制中心 | 12 |
| `stroke-hairline` | 1 | 栅栏边框、分隔线 | 固定 2px，偏重 |
| `stroke-emphasis` | 2 | 选中强调框 | 3，偏重 |

### 2.2 字号层级

| 层级 | 字号 / 字重 | 用途 | 现状 |
|---|---|---|---|
| `type-panel-title` | 16 semibold | 控制中心标题 | 16 regular |
| `type-fence-title` | 13 semibold | 栅栏标题 | **16 regular**，比名称大 33%，压内容 |
| `type-label` | 12 | 图标名称 | 12 |
| `type-detail` | 11 | 列头、辅助说明 | `12 × 0.72 = 8.6`（`draw.rs:117`），中文糊 |

> `type-detail` 只有 8.6px 是当前控制中心"发虚"的直接原因，建议直接提到 11px。

### 2.3 单元格三档规格（核心表）

**不变式**：格高由档位决定，**与名称开关无关**；图标高度 = 格高 − 标签块；名称永远单行。

| 档位 | 格宽 × 格高 | 图标（名称开） | 图标（名称关） | 名称字号 | 名称可读宽 | ≈中文字数 |
|---|---|---|---|---|---|---|
| 小（紧凑） | 64 × 64 | 32 | 40 | 12 | 56 | 4–5 |
| 中（默认） | 80 × 80 | 48 | 60 | 12 | 76 | 6 |
| 大（媒体） | 104 × 96 | 64 | 80 | 12 | 96 | 8 |

计算规则（可直接落成函数，供布局 / 绘制 / 编辑框 / 控制中心共用）：

```text
cell_h   = 档位常量（64 / 80 / 96）
cap_h    = show_labels ? (label_size + 4) : 0      // 行高 + 间距
icon_on  = cell_h - cap_h - 12                      // 上下各 6 呼吸
icon_off = min(icon_on * 1.25, cell_w - 12, cell_h - 12)
cell_w   = 档位常量（64 / 80 / 104）
```

这套规则同时解决三件事：三档可预期、名称开关不重排、图标与名称永远不打架。

## 3. 逐条回应

### 3.1 网格"大中小"三档要受控

**现状**：`ConsoleZone::FenceIconSize` 只写 `icon_size`（`main.rs:1402-1409`），不改栅栏尺寸、不改 gap、不改字号；格宽是 `max(icon + gap, icon × 1.5)`（`app/scene.rs:1328`），行高是另一个公式（`:1333`）。

**问题**：
- 切到"大"后列数骤减、内容溢出，但栅栏宽高不动 → 出现滚动条 + 右侧大片空白；
- 三档的可读字符数从 ~7 变成 ~15，同一个文件名在三档下截断位置完全不同；
- 用户无法调"间距"（`gap`/`padding` 已持久化却没有 UI 入口）。

**建议**：
1. 三档改为"**格**的三档"（见 §2.3 表），档位同时决定格宽、格高、字号；
2. 切换档位后**同步重算栅栏尺寸**：列数不变则宽度 = 格宽 × 列数 + padding × 2（复用 `resize_fence_to_grid`，`main.rs:2326`），并做一次安全区钳制；
3. 控制中心增加"密度"控制（紧凑 / 标准 / 宽松），只改格内呼吸与间距，不改格子尺寸；
4. 间距、内边距补上入口（或明确删除这两个持久化字段，别留"假设置"，见 §4-P0-2）。

**落点**：`core/model.rs`（新增 `CellSize` 枚举替代裸 f32）、`app/scene.rs`（`grid_cell_w` / `grid_row_h` 合并成 `cell_metrics()`）、`render/theme.rs`、`app/main.rs`（`FenceIconSize` 改为 `FenceCellSize`）。

**验收**：三档来回切换 3 次，栅栏宽高、列数、图标、名称都可预期且不出现滚动条；重启后保持。

### 3.2 整个桌面需要内边距

**现状**：拖动/缩放时栅栏的边界是 `work_area_rect`（`app/main.rs:845`，返回**主显示器**任务栏扣除后的区域），直接作为 `settle_move / settle_resize` 的边界（`:955`、`:980`）——**没有内缩**，栅栏可以 0 间距贴住屏幕边缘和任务栏。启动恢复走的却是 `clamp_into_screen`（`:2067`，虚拟屏边界），两套语义不一致。

**问题**：
- 贴边 0 间距，视觉上栅栏"粘"在屏幕上；
- `SPI_GETWORKAREA` 只认主屏：副屏上的栅栏会被夹回主屏；虚拟屏中间也可能落进两块屏之间的空隙；
- 拖动用工作区、重启用虚拟屏，重启后栅栏可能落到任务栏下面；
- 新栅栏固定落在 `(80,120)`（`:2274`），撞到已有栅栏后再被推挤，落点不可控。

**建议**：
1. 新增 `DESKTOP_INSET = 12`：栅栏可放置区 = 每块显示器的 `rcWork` 内缩 12px；
2. 栅栏归属按"中心点所在显示器"判定，顺手把恒为 0 的 `monitor_id`（`core/model.rs:372`）用起来；
3. 启动时做一次归一化：越界的栅栏推回安全区（一次性写回）；
4. 新栅栏落点：安全区内从左上扫描第一个不冲突位置，找不到再退回 `settle_move`。

**验收**：四边贴边拖动都被"弹"回 12px；双屏中间拖动不掉进缝隙；断掉副屏后重启，原副屏上的栅栏全部回到主屏安全区内。

### 3.3 调整大小要有对齐辅助线

**现状**：没有辅助线，也没有吸附——`core/magnet.rs:3-7` 明确写着"不再吸附对齐"，只做"永不重叠 + 最小间隙"。

**问题**：结果是"能对齐，但全靠手感"。两个栅栏差 3px 完全看不出来，用户只会觉得"乱"。

**建议**（保留硬约束，只增加"辅助"）：
1. **候选线**：每个邻居的 左/右/水平中心 / 上/下/垂直中心，共 6 条；再加安全区 4 条边与屏幕中轴 2 条；
2. **吸附**：阈值 6 DIP，取 |Δ| 最小者；按住 `Alt` 临时禁用；
3. **绘制**：1px 实线、白色 45%，延伸到被对齐对象的边界；同一轴线只画一条（去重）；
4. **尺寸徽标**：拖拽/缩放时在栅栏右下角外侧显示 `宽 × 高`，松手消失（可选 `列 × 行`）；
5. **顺序**：先吸附 → 再跑 `settle_move / settle_resize`；若推挤改变了位置，**按最终位置重算参考线**（宁可线消失，也不要"线在但没对齐"）；
6. **等距提示**（P2）：与左右邻居间距差 ≤ 2px 时，显示 `12 | 12` 的双向间距徽标。

**落点**：`core/magnet.rs` 新增纯函数 `snap_align(rect, others, bounds) -> (rect, guides)`（可单测）；`render/scene.rs` 增加 `guides: Vec<GuideLine>`；`render/draw.rs` 画线；`app/main.rs` 的 `FenceMove / FenceResize` 分支串起来。

**验收**：拖动时能"啪"地贴上邻居左边缘并出现线；Esc/松手后线消失；双屏与 150% 缩放下线仍然对齐 1px。

### 3.4 标题高度 = 网格单元高度

**现状**：标题带 = `title.size × 1.6 + title_padding_bottom` = `16 × 1.6 + 10` = 35.6（`app/scene.rs:982`），再加一份 `pad` 共 47.6；而一格行高是 `48 + 6 + 31.2` = 85.2（`:1333`）。标题文字上边距 14px（还被 `fence_padding` 多推了 2px），下边距却有 20px。

**问题**：标题与内容不在同一节奏上，多栅栏并排时首行图标永远对不齐；折叠态（`FenceState::Folded` 目前**从未被使用**）也没有合适的基准高度。

**建议**：
- 顶部内边距 + `header_h` = `cell_h / 2`（标题带 = 半格减去内边距，标题在带内**水平 + 垂直居中**）；
- 标题与内容之间不再额外加 `pad`，靠格内 6px 呼吸；
- 字号降到 13 semibold（16px 标题在 48px 图标旁太重）；
- 折叠态高度 = `header_h`，视觉上"就是一个格子"。

> 取舍：若觉得 `cell_h` 作为标题带过高，退一步的方案是 `header_h = cell_h − cap_h`（即"图标行高"）。两种都满足"与格子同节奏"，但推荐前者——折叠后的栅栏才像桌面小组件。

**验收**：两个不同档位的栅栏并排，标题基线与第一行图标垂直中心对齐；折叠后高度正好一格。

### 3.5 名称单行、居中；名称显示时图标缩小

**现状**：名称最多两行（`GRID_CAPTION_H_MULT = 2.6`，`draw.rs:1384`），**左对齐**（`make_text_format` 从未设置 `SetTextAlignment`，`draw.rs:2047-2071`），图标高度恒定。

**问题**：格子里的图标居中、名称却左对齐，视觉上是"歪的"；两行名称让同一个栅栏里图标"高低不齐"；名称为空时还占着两行高度。

**建议**：
1. **单行 + 居中**：网格布局新增一个 `label_center` 文本格式（`TEXT_ALIGNMENT_CENTER` + `PARAGRAPH_ALIGNMENT_CENTER`）；
2. **超长截断**：一行放不下时**尾部省略号**，而不是换行；完整名称交给现有悬停 tooltip；
3. **图标自适应**：`icon_on = cell_h − cap_h − 12`，关名称时按 `×1.25` 放大但不超格（见 §2.3）；
4. 列表布局保持左对齐（有列结构），只改网格。

> 关于"超过则不显示"：建议保留省略号。完全不显示会让 8 字文件名看起来像 4 字，用户会误判；省略号是最低成本的"还有内容"信号。

**验收**：文件名 4/8/16 字在三档下都是单行居中；开关名称时格子不移动，只有图标缩放；中英文混排不溢出。

### 3.6 点栅栏 → 控制中心切到该栅栏的设置页

**现状**：`ConsoleZone::FenceSelect`（`main.rs:1343`）只能从控制中心内部选中栅栏；**栅栏本身没有单击事件**——点标题要么开始拖动，要么什么都不发生。目前唯一的入口是右键"在控制中心管理此栅栏"（`context_menu.rs:334`）。

**建议**：把标题栏设计成三个手势，互不冲突：

| 手势 | 行为 |
|---|---|
| 单击（位移 < 5px） | 新增 `OverlayEvent::FenceClicked { fence }`：控制中心若已打开 → 切到 Fence 页 + 选中 + 列表滚动到可见；未打开 → 仅选中 |
| 双击 | 折叠 / 展开（把闲置的 `FenceState::Folded` 用起来） |
| 拖动 | 移动（现状不变） |

配套：
- 控制中心选中 → 实体栅栏高亮（已有，`draw.rs:1146`），建议加 200ms 脉冲，让"切过去了"有反馈；
- `Esc` 关闭控制中心（现在没有，容易困在里面）；
- 设置页分三组：**布局**（布局/密度/行列）、**外观**（风格/色调/形状/悬停/标题/名称）、**内容与危险区**（存储/隐藏/删除），组间 20px，组内 8px。

**验收**：控制中心开着时点任意栅栏标题，右侧内容瞬间切换且列表高亮同步；双击折叠；Esc 关闭。

## 5. 建议落地顺序

| 批次 | 内容 | 为什么先做 | 预估改动面 |

## 7. 落地进度（2026-11-15）

### 已实现

**B1 度量体系**

- `core::model::CellSize`（小 / 中 / 大）+ `core::layout::cell_metrics()`：一个档位同时给出格宽、格高、图标、名称行；布局、绘制、就地编辑框、控制中心共用。
- 持久化 v4 迁移：旧 `icon_size` 读入 `legacy_icon_size`，由 `normalize()` 折算为档位后丢弃，不回写。
- 标题占半格：顶部内边距 + 标题带 = 半格，13px semibold 水平 + 垂直居中（`theme.fence_title` + `TextFormats::fence_title`，公式在 `core::layout::header_height`）。
- 网格名称单行、水平+垂直居中、超长省略（`TextFormats::label_center`）；列表保持左对齐。
- padding 单源：`SceneFence.padding`，标题、裁剪、滚动条、命中模型共用 `appearance.padding`。
- 删除 4 个假设置（`corner_radius` / `title_bar_height` / `acrylic` / `border_width`）。
- 强调色收敛到 `theme.accent`；辅助文字 8.6 → 11px；常态描边 2 → 1px；图标提取 64 → 96。
- DPI / 屏幕尺寸变化时重建 DWrite 文本格式（`Compositor::set_theme`）：此前字号只在启动时生效，缩放后文字与布局脱节。

**B2 桌面安全区与对齐辅助**

- `DESKTOP_INSET = 12`：拖动、缩放、启动恢复、新建落点统一使用「所在显示器 work area 内缩」。
- `snap_move / snap_resize`（阈值 6 DIP，`Alt` 关闭）与 `alignment_guides`：只画真实成立的对齐线。
- 拖拽时的 `宽 × 高` 徽标（栅栏右下角内侧，随拖拽消失）。

**B3 控制中心联动**

- 单击标题：选中栅栏 + 控制中心切到该栅栏页 + 列表滚动到可见。
- 双击标题：折叠 / 展开；展开后恢复原高度（`bounds.h` 不动，折叠态高度由布局覆盖）。
- `Esc` 关闭控制中心。

### 2026-11-15 追加修复

- **固定列数被静默降级**：8×8 选择器设的列数高于栅栏实际能容纳时，布局把 `cols` clamp 成 `auto_cols`，图标换行。现已改为**列数优先**：`grid_cols > 0` 时列数不变、格宽在 `[图标+8, 档位格宽]` 内压缩；只有自动列数才按档位格宽换列。
- **任务栏**：可见任务栏由 `rcWork` 扣除；自动隐藏任务栏读取 `SHAppBarMessage(ABM_GETTASKBARPOS/ABM_GETSTATE)`，在所在边额外预留厚度。
- **假滚动条**：可滚动范围扣掉 0.5px 内的舍入误差（`scroll_range`），固定行列高度改用 `ceil`，滚动条绘制阈值同步；修掉「有滚动条但没内容可滚」。

### 2026-11-15 追加修复（二）

- **固定行数栅栏的高度改为派生**：以前 `resize_fence_to_grid` 把高度写死进 `bounds.h`，指标（标题带半格、格高）一变就成为陈旧值，底部留一条空白。现在设了可见行数时高度恒等于「上下 padding + 标题带 + 行数 × 格高」，不再持久化；启动/DPI/显示变化时先夹屏再清旧值。未设行数、用户手拖过的栅栏仍保留手动高度。

### 2026-11-15 追加修复（三）

- **2×2 右侧空白**：固定列数时格宽改为**铺满**内容区（原先上限是档位格宽，栅栏更宽就会在右侧留白）。
- **栅栏内拖拽排序**：overlay 新增 `GridReorder` 拖拽态（栅栏内超过阈值进入排序、离开栅栏切回拖出/分类），松手由 `slot_index_at` 算插入槽并写回 `icon_ids`；渲染层只做"其余图标让位 + 拖动项跟随光标"的预览。
- **溢出格**：容量不足时最后一格折叠成 3×3 缩略图 + 计数；点击/双击展开（忽略容量、显示全部并滚动），再点或 Esc 收起。只读镜像不显示排序预览。
- **隐藏栅栏不占位**：碰撞、启动消解、合成表面都跳过 `hidden` 栅栏。

### 一个可调项

标题带按需求实现为 `header_h = cell_h`（中档 80、大档 96）。若实际观感偏高，把 `layout_fence` 与 `hit_model_from` 里的 `cell.cell_h` 换成 `cell.cell_h - cell.caption_h`（一格中的图标行）即可，其余逻辑不变。
